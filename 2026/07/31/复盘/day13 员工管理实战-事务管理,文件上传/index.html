2.事务管理

为什么需要事务

新增员工涉及两次数据库操作（插emp表 + 插emp_expr表）。如果保存员工成功、保存经历失败，就会造成数据不完整不一致。事务能让多个操作要么全部成功，要么全部失败。

事务概念与操作
  • 概念： 一组操作的集合，是不可分割的工作单位，要么同时成功，要么同时失败
  • SQL层面三步操作：
    • 开启事务：start transaction; / begin;
    • 全部成功：commit;
    • 有失败：rollback;

注意：MySQL默认事务是自动提交的，执行一条DML语句会立即隐式提交。

Spring事务管理：@Transactional注解

作用： 方法执行前开启事务，执行完毕提交事务，出现异常则回滚事务。

可加的位置：

位置 作用
方法上 当前方法交给Spring事务管理
类上 当前类所有方法都进行事务管理
接口上 接口下所有实现类的所有方法都进行事务管理

为什么放在业务层？ 一个业务功能可能包含多个数据访问操作，在业务层控制事务可以将多个操作控制在同一个事务范围内。

事务日志配置
rollbackFor属性（异常回滚）

默认规则： 只有出现**运行时异常（RuntimeException）**才回滚事务；抛出编译时异常（Exception）不会回滚。

解决： 通过 rollbackFor 指定回滚的异常类型。

结论：

  • 默认只有 RuntimeException 会回滚
  • 需要回滚其他异常时，用 rollbackFor 属性指定
propagation属性（事务传播行为）

概念： 一个事务方法被另一个事务方法调用时，这个事务方法应该如何进行事务控制。

属性值 含义 使用场景
REQUIRED（默认） 需要事务，有则加入，无则新建 大部分情况
REQUIRES_NEW 总是创建新事务 不希望事务相互影响（如记日志）
SUPPORTS 有则加入，无则无事务运行 少用
NOT_SUPPORTED 无事务状态下运行 少用
MANDATORY 必须有事务，否则抛异常 少用
NEVER 必须没有事务，否则抛异常 少用

案例：新增员工时无论成功失败都记录日志

问题：save方法有事务，insertLog默认REQUIRED会加入同一事务 → 主事务回滚时日志也被回滚，日志没记上。

解决： 让insertLog独立开启新事务。

两个必须掌握的传播行为：

  • REQUIRED： 大部分情况下使用，加入已有事务
  • REQUIRES_NEW： 不希望事务互相影响时使用，如记录日志（无论业务成功与否日志都要记上）
事务四大特性（ACID）
特性 英文 说明
原子性 Atomicity 事务是不可分割的最小单元，要么全部成功，要么全部失败
一致性 Consistency 事务完成时，数据都必须处于一致状态
隔离性 Isolation 多个并发事务之间相互隔离，互不干扰
持久性 Durability 事务提交或回滚后，对数据的改变是永久的

4.配置参数优化（@Value vs @ConfigurationProperties）

问题： endpoint、bucketName等参数写死在Java代码中，测试/生产环境切换不便维护。

方式一：@Value注解逐个注入

适用： 一两个属性、不需要复用。

方式二：@ConfigurationProperties批量绑定（推荐）

三个步骤：

  1. 创建实体类，属性名与配置key一致
  2. 将实体类交给IOC容器管理（@Component）
  3. 实体类上添加 @ConfigurationProperties(prefix="...") 指定前缀

对比：

方式 优点 缺点
@Value 简单直接 配置项多时繁琐，不便维护复用
@ConfigurationProperties 批量注入，便于维护复用 需要额外建实体类

5.核心知识点总结

知识点 说明
@PostMapping + @RequestBody 接收JSON格式的新增请求
@Options(useGeneratedKeys, keyProperty) 主键返回，自增主键回填到对象id属性
<foreach> 批量插入，collection/item/separator/open/close
CollectionUtils.isEmpty 判断集合是否为空
事务 一组操作的集合，要么全部成功要么全部失败
@Transactional 开启事务管理，异常自动回滚
事务注解位置 业务层方法/类/接口上
rollbackFor 默认只回滚RuntimeException，rollbackFor=Exception.class回滚所有异常
REQUIRED 默认传播行为，有事务则加入
REQUIRES_NEW 总是创建新事务，互不影响（如记日志）
ACID 原子性、一致性、隔离性、持久性
上传三要素 file域 + POST + enctype=”multipart/form-data”
MultipartFile 接收上传文件，transferTo转存磁盘
UUID文件名 解决文件名重复覆盖问题
max-file-size SpringBoot默认单文件最大1M，需配置调大
阿里云OSS 对象存储服务，解决本地存储的缺点
SDK 软件开发工具包，含依赖和示例代码
@Value 单个属性注入配置
@ConfigurationProperties 批量绑定配置到实体类，便于维护复用
